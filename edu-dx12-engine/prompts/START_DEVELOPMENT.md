# Codexへ渡す初回プロンプト — M00

以下の枠内を、準備ファイルを配置したプロジェクトのCodexへ渡してください。

```text
$build-educational-dx12-engine

このリポジトリの AGENTS.md と .agents/skills/build-educational-dx12-engine/SKILL.md を読み、教育用ゲームエンジン開発コパイロットとして進めてください。

今回は [開発モード] です。まず docs/PROJECT.md、docs/STATUS.md、docs/ROADMAP.md のM00、docs/DEPENDENCIES.md、docs/VALIDATION.md の関連箇所を読み、M00だけを実施してください。

目的は、C++20 / DirectX 12の教育用エンジンを作り始めるための環境とビルドの土台を確定することです。読みやすさと授業で説明しやすい構造を最優先してください。

実施すること：
1. 既存ファイルと変更状態、OS、利用可能なコンパイラ、CMake、Windows SDK、ビルドツールを確認し、実測値と未確認項目を記録する。
2. docs/DECISIONS.md の暫定方針と実環境を比較し、必要な分岐だけ2〜3案で比較する。既定の方針で問題なければ採用して進む。
3. 最小のCMakeLists.txtとCMakePresets.jsonを作り、C++20設定とWindows描画部分／移植可能なCPU部分の境界を用意する。この段階で必要なファイルだけ作る。
4. 採用したpresetとビルドターゲットを具体化し、利用可能な環境でconfigure/buildする。コードなしのconfigure確認と、実際にコンパイルした検証を区別する。必要なら空のダミーテストではなく、小さな実働の環境確認プログラムを使う。
5. 実行コマンド、バージョン、終了コード、ログを docs/DEPENDENCIES.md と docs/STATUS.md に記録し、READMEの開始手順を実際の設定と合わせる。

今回の範囲外：Win32ウィンドウ実装、DX12初期化、三角形、Nodeの実装、PBR、RenderGraph、ImGui、Lua、Effekseer、音声の導入。ライブラリを一括取得しない。

Windows環境へアクセスできない場合も可能な環境調査とCPU側の土台作成は進め、Windowsでの確認は「未実施」と記録してください。Linuxでの成功をDX12の成功とは扱わないでください。

モードと開始段階は既に指定済みなので再質問は不要です。可逆的な実装判断は理由を記録して進めてください。ツールの導入・設定変更が現在の許可範囲を超える場合は、可能な作業を先に済ませ、必要な操作だけ具体化してください。

最後に「実施したこと」「確認できた結果」「未実施・残課題」「M01へ進むための次の一手」を報告してください。M00だけでエンジン完成とは表現しないでください。
```
