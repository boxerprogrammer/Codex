# プロジェクト方針

作成日：2026-11-25。仮称：**教育用DX12エンジン**。正式名称は未決定で、実装開始の妨げにはしない。

## 目的

専門学校の学生が「コードを動かせる」だけでなく、「このクラスがなぜ必要か」「データと処理の寿命がなぜ違うか」を説明できる小さなゲームエンジンをC++20 / DirectX 12で作る。実装と一対一に対応する日本語の授業資料・演習を育てる。

優先順位：**理解しやすさ・可読性 > 拡張性 > 授業・教材への転用 > 機能性・実行効率**。

## 学生像

| 項目 | 前提 |
| --- | --- |
| 既習 | C++のクラス、ポインタ、継承、STLの基礎 |
| 未経験または苦手 | DX12、メモリ配置、GPU同期、大きなクラス構造 |
| 授業の到達点 | 責務分割と処理順を図にし、理由を言葉で説明できる |
| 実習の到達点 | 小さな機能を追加し、失敗をログ・デバッガ・GPUツールで調べられる |

## ユーザーが指定した要件

| 要件 | 準備段階の扱い | 主な段階 |
| --- | --- | --- |
| C++20 / DirectX 12 / HLSL | 必須。C++例もC++20を守る | 全体 |
| Visual Studio 2026 | Windows x64での実装・検証対象 | 全体 |
| PBR / Unlit切替 | 最終版で必須。PBRは直接光の基本形から | M06 / M08 |
| 簡易RenderGraph / FrameGraph | 必須。教育向けに限定した仕様 | M07 |
| ImGui | インスペクタ・デバッグ・リソース表示に導入 | M09 |
| Effekseer | エフェクトの再生・更新・終了処理を統合 | M12 |
| Lua、必要に応じsol2 | 安全なC++連携とスクリプトエラー処理 | M10 |
| XAudio2またはCRIの無料版 | 初期案はXAudio2。CRIは条件確認後に比較 | M11 |
| GodotのNode / Scene / Resourceを参考にする | 概念と責務を参考にし、小さく独自実装 | M05以降 |
| 開発と教材執筆の2モード | 依頼に応じ切替。明示指定を優先 | 全体 |
| 設計分岐で2〜3案比較 | 重要な分岐で実施。授業難易度を併記 | 全体 |

## 暫定採用する設計

以下は、ユーザーが詳細まで指定した事実ではなく、この準備パックの推奨初期案。根拠と変更条件は[DECISIONS.md](DECISIONS.md)に記録する。

- Windows x64の共通CMakeプリセットは、Visual Studio 2026のMSVC v145を使う。検証環境の具体版は依存関係の文書に記録する。 [実測記録](DEPENDENCIES.md#24-visual-studio-2026の実測記録)
- Nodeの小さな派生クラスとデータの合成。汎用Componentシステム・ECSは最初に導入しない。
- Sceneがrootを単一所有し、Nodeが子を単一所有。共有素材はResource、描画GPU資産の寿命はRendererで管理する。
- DirectX 12専用の分かりやすい実装から始める。複数描画APIを抽象化するRHIは作らない。
- RenderGraphは明示的な順序で実行する単一direct queue。並べ替え・aliasing・非同期computeは発展扱い。
- サウンドはXAudio2の短いPCM WAV再生から。外部ミドルウェア統合は段階ごとに実施する。
- 左手系、Y-up、+Z前方、メートル、ラジアン。行ベクトル・`row_major`・通常Zに統一する。
- PBR導入後の起動時標準はPBR、設定とマテリアルの明示指定でUnlitへ切替可能にする。PBR導入前の各サンプルはUnlitのみと記す。

## 段階的な成果

| 区切り | 見える成果 | この時点で未対応のもの |
| --- | --- | --- |
| M00〜M02 | 自分の環境でウィンドウを出し、DX12で背景色を描ける | メッシュ、Scene、PBR、外部統合 |
| M03〜M06 | 三角形から3Dメッシュへ進み、NodeツリーとUnlit素材を扱える | RenderGraph、PBR、ImGui等 |
| M07〜M08 | 描画パスの依存・状態遷移を追い、PBR / Unlitを比較できる | IBLや高度な物理表現、全外部統合 |
| M09〜M12 | デバッグUI、スクリプト、音、エフェクトを一つずつ加える | 本格的なエディタ、複雑な配信機構 |
| M13 | 小さな総合サンプル、説明文書、学生課題と講師解答を揃える | 汎用商用エンジン相当の機能 |

各段階は「実装完了」と「その段階に必要な検証完了」を区別する。段階が終わるたびに再承認を求めるのではなく、依頼された到達範囲まで進める。最初の開始プロンプトはM00だけに範囲を設定している。

## 初期の対象外

フル機能のエディタ、プラグインABI、マルチプラットフォームRHI、Vulkan、ネットワーク、商用物理統合、DXR、mesh shader、GPU driven描画、bindless、独自ジョブシステム、非同期compute、transient aliasing、巨大なECS、シェーダ自動生成は初期範囲外。将来採用するときは、学習目的・前提・影響範囲を明示して別の段階を作る。

## 初回対話の扱い

何も決まっていない会話の初回は、役割を名乗ってモードと着手トピックを尋ねる。`START_DEVELOPMENT.md`のように対象が既に示されている場合は、「開発モードでM00から進めます」と確認して作業を始める。

本パックを作る今回の依頼は**開発前の文書整備**。エンジン実装、PCへのSDK導入、GPU動作確認が済んだとは扱わない。

- 固定されたユーザー要件を変える場合は変更内容と影響を説明する。

- 各タスクの開始・終了は[STATUS.md](STATUS.md)で引き継ぐ。
